# 샘플 ⑤ TankBattle `★5 고급`

클라이언트 예측 · 서버 보정 · 지연 보상까지 넣은 미니 대전 액션.
**이 라이브러리로 만드는 실전 아키텍처의 결정판**이다.

## 실행

```bash
# 혼자서도 테스트할 수 있게 봇 7대를 넣는다
dotnet run --project samples/05-TankBattle/Server -- --bots 7
dotnet run --project samples/05-TankBattle/Client -- 127.0.0.1 me
```

UDP **27005** 포트. 최대 8명.

| 조작 | 동작 |
|---|---|
| `WASD` / 방향키 | 이동(전후진 + 회전) |
| 마우스 | 포탑 조준 |
| `Space` | 발사 |
| `F1` | **예측 on/off 토글** — 핵심 실습 |
| `ESC` | 종료 |

서버 옵션: `--bots N`(0~7), `--no-lagcomp`(지연 보상 끄기).

## 배우는 것

1. **클라이언트 예측** — 서버 응답을 기다리지 않고 내 입력을 즉시 화면에 반영
2. **서버 보정(reconciliation)** — 서버 상태로 되감고 미확인 입력을 재적용
3. **입력 중복 전송** — 최근 3개 입력을 한 비신뢰 패킷에 실어 손실 견디기
4. **지연 보상(lag compensation)** — 서버가 과거 1초를 되감아 "내 화면 기준" 히트 판정
5. **서버 검증** — 이동 속도·발사 쿨다운을 서버가 강제(치트 방지 기초)

## 세 가지 지연 대응책이 어떻게 맞물리나

| 문제 | 해법 | 어디에 |
|---|---|---|
| 내 입력이 RTT만큼 늦게 반영된다 | **예측** — 즉시 적용하고 나중에 맞춘다 | `Client/Prediction.cs` |
| 다른 탱크가 20Hz로 뚝뚝 끊긴다 | **보간** — 100ms 늦게 재생하며 사이를 메운다 | `Client/TankBattleGame.cs` |
| 잘 조준했는데 빗나간다 | **지연 보상** — 서버가 과거로 되감아 판정한다 | `Server/LagCompensator.cs` |

세 가지 모두 **"지연을 없앨 수는 없으니 어디로 옮길지 정한다"**는 같은 사고방식이다.

## 예측과 보정이 도는 방식

```
[클라] 입력 #42 생성 → 즉시 내 화면에 적용 → 서버로 전송(비신뢰, #40·#41과 함께)
[서버] #40, #41, #42 순서대로 적용 → 스냅숏에 "마지막 처리 = #42" 를 실어 보냄
[클라] 스냅숏 수신
       ├ 서버가 준 위치를 진실로 받아들이고
       ├ #42 이하의 미확인 입력을 목록에서 제거한 뒤
       └ 남은 입력(#43, #44…)을 그 위에 다시 적용 → 현재 화면
```

예측이 맞았다면 재적용 결과가 기존 화면과 같아 **아무 일도 일어나지 않는다**.
틀렸다면(경계 클램프, 서버의 쿨다운 거부 등) 그때만 위치가 보정된다.
HUD의 `CORRECTIONS` 가 그 횟수이며, 로컬에서는 대개 0에 가깝다.

> **이것이 성립하려면 물리가 순수 함수여야 한다.** `Shared/TankPhysics.cs` 에 난수도 시간도 없는 이유다.
> `Tests/TankPhysicsTests.cs` 의 `되감아_재적용해도_같은_결과가_나온다` 가 이 성질을 못 박는다.

## 지연 보상 되감기 계산

```
사수가 보고 있던 시점 = 지금 − (RTT/2 + 보간 지연 100ms)
되감을 틱 수          = 그 시간 ÷ 50ms(20Hz)
```

RTT 60ms면 (30 + 100) / 50 ≈ **2~3틱**을 되감는다. 서버 로그에 `킬 A -> B (되감기 2틱)` 으로 찍힌다.
`--no-lagcomp` 로 끄고 지연을 걸어 보면 조준이 잘 맞지 않는 것을 체감할 수 있다.

되감기 상한은 1초(`HistoryTicks = 20`)다. 무제한이면 "한참 전 위치를 쏘는" 악용이 가능해진다.
그리고 대가로 **맞은 쪽에서는 "숨었는데 맞았다"** 가 생길 수 있다 — 모든 대전 액션이 감수하는 절충이다.

## 채널 배분

| 데이터 | 채널 | 주기 |
|---|---|---|
| 입력(최근 3개 묶음) | 비신뢰 | 30Hz |
| 스냅숏 | 비신뢰 | 20Hz |
| 입장/퇴장, 발사·피격·사망, 점수판 | 신뢰 | 이벤트 |

입력을 3개씩 겹쳐 보내므로 **연속 2패킷이 유실돼도** 서버는 입력을 놓치지 않는다.
재전송이 아니라 중복 전송으로 손실을 이기는 방식이며, 지연이 늘지 않는 것이 장점이다.

## 직접 확인해 볼 것

1. **예측 끄기** — `F1` 로 끄고 clumsy 등으로 100ms 지연을 걸면 조작이 확실히 둔해진다.
   켜면 로컬과 구분하기 어렵다. **이 차이가 예측이 하는 일 전부다.**
2. **보정 횟수** — HUD의 `CORRECTIONS`. 벽으로 계속 밀고 들어가면(서버가 클램프) 늘어난다.
3. **지연 보상 비교** — `--no-lagcomp` 로 서버를 띄우고 지연을 건 뒤 움직이는 표적을 쏴 본다.
4. **틱 예산** — 서버가 5초마다 `틱 처리 최대 N ms` 를 찍는다. 8인(봇 7 + 사람 1)에서 1ms 안쪽이다.
