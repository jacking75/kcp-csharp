# KcpCSharpR1 0.11.0

Game integration and transport reliability improvements. Both `KcpCSharpR1` and
`KcpCSharpR1.Transport` are released together at version **0.11.0**.

## 주요 변경

- 연결 취소·실패·재연결의 소켓/세션 자원 회수와 중복 연결·구동 모델 혼용 검사를 보강했다.
- 서버 종료는 진행 중인 콜백이 끝난 뒤 자원을 회수한다. 콜백 내부 종료 요청은 자기 대기 없이 처리한다.
- 메시지 조각 번호 한도, MTU 변경, 스트림 송신의 부분 반영, 조각난 메시지의 백프레셔 오류를 수정했다.
- `CipherFactory`로 연결마다 독립된 사용자 정의 암호화기를 생성·검증·해제한다.
- 변조·리플레이·잘못된 KCP 데이터가 정상 수신 시각을 갱신하지 않도록 수정했다.
- `DisconnectOnCriticalOverflow` 큐 정책과 유형별 유실 누계, `HasCriticalOverflow`를 추가했다.
- MonoGame 샘플 3종이 연결 결과와 수신 이벤트를 게임 스레드에서 처리하도록 수정했다.
- [한국어 게임 연동 가이드](https://github.com/jacking75/kcp-csharp/blob/v0.11.0/docs/game-integration_kr.md)와
  [English guide](https://github.com/jacking75/kcp-csharp/blob/v0.11.0/docs/game-integration.md)를 추가했다.

## 0.10.0에서 업그레이드할 때

코어 KCP 와이어 형식과 타깃(`net8.0`, `netstandard2.1`)은 유지한다. 아래 동작 변경은 확인해야 한다.

1. **서버의 `Session.Cipher` 직접 지정은 거부한다.** 여러 세션이 암호화기 상태를 공유하지 않도록
   `CipherFactory`와 `CipherFactoryOverhead`를 사용한다. 팩터리는 `(conversation, serverDirection)`을
   받고 매번 새 인스턴스를 반환해야 한다. 선언한 오버헤드와 실제 `IPacketCipher.Overhead`는 같아야 한다.
   내장 .NET 8 AES-GCM을 사용한다면 기존처럼 `EncryptionKey`를 지정하면 된다.
2. **암호화 설정은 하나만 지정한다.** `Cipher`, `CipherFactory`, `EncryptionKey`의 중복 지정과
   RawMode의 암호화/FEC 조합은 예외로 거부한다. 잘못된 타이머·윈도·서버 한도도 조기에 거부한다.
3. **옵션은 생성 시 복사한다.** 생성 후 원본 옵션을 변경해 실행 중 클라이언트/서버/세션을 조정할 수 없다.
4. **연결 태스크가 완료된 후에 `Update` 또는 `RunAsync`를 호출한다.** 활성 연결 덮어쓰기,
   서버의 중복 시작, 백그라운드 수신 루프와 수동 `Pump` 혼용도 거부한다.
5. **외부의 서버 `Stop`은 실행 중인 콜백 종료까지 기다린다.** 콜백에서 블로킹 작업을 하지 않는다.
   콜백 안의 `Stop`/`Dispose`는 종료를 요청하고 반환한 뒤 실제 자원을 회수한다.
6. **송신 결과를 확인한다.** 메시지 전체 조각이 백로그 한도에 들어가지 않으면 `Backpressure`가 반환된다.
   송신 대기 데이터가 있을 때 MTU/예약 크기를 바꾸면 거부된다.

기존 `EnableEventQueue(capacity)`의 `DropNewest` 정책은 유지한다. 중요 이벤트 유실 후 연결을
계속하지 않으려면 다음처럼 명시한다. 종료 이벤트 자체도 큐 포화로 누락될 수 있으므로
`HasCriticalOverflow`와 누계 변화를 관측해야 한다.

```csharp
var events = client.EnableEventQueue(
    1024, KcpEventQueueOverflowPolicy.DisconnectOnCriticalOverflow);
```

## 설치

게임 클라이언트/서버는 Transport만 추가하면 코어가 자동으로 설치된다.

```bash
dotnet add package KcpCSharpR1.Transport --version 0.11.0
```

기존 코어 단독 사용자는 `KcpCSharpR1`을 `0.11.0`으로 갱신한다.

- 단위·시뮬레이션·실소켓·샘플·소크 테스트 **317개 통과**.

- 격리 NuGet 소비자로 두 타깃의 실제 UDP 연결 취소·재시도, 신뢰/비신뢰 에코,
  조각 재조립·순서, 송신 아웃박스와 정상 종료 검증. 복원한 패키지 해시와 로드된 DLL 타깃도 검사한다.
- 같은 환경의 코어 1KB/32KB 송수신 비교에서 측정 오차를 넘는 성능 저하 없이 0 B/op를 유지했다.

Windows에서 검증했다. `netstandard2.1` DLL의 실행 호스트는 .NET 8이며,
다른 게임 엔진·모바일·콘솔·AOT 런타임 인증을 뜻하지 않는다.

## 지원 범위

내장 AES-GCM은 `net8.0` 타깃에서 제공한다. `netstandard2.1` 암호화는 호환 `IPacketCipher` 팩터리가
필요하며 FEC와 암호화는 함께 사용할 수 없다. 프로토콜 v1은 KCP/RAW 페이로드를 인증하고,
핸드셰이크·PING·PONG·FIN은 인증 범위에 포함하지 않는다. 키 교부와 플레이어 인증은 애플리케이션 책임이다.
서버 인스턴스를 새로 만들거나 대화 번호가 순환할 때 같은 키·nonce를 재사용하면 안 된다.
